# HMW Priority 1 アイデア発散

**HMW-12: どうすれば、「調べない」ペルソナでも、知識が自然に蓄積されるようにできるだろうか？**

[[hmw-prioritized#🥇-priority-1-hmw-12|Priority 1の詳細]]を参照。

---

## アイデア発想の原則（授業より）

1. **アイデア = 既存の要素の新しい組み合わせ**
2. **段階的に発想する**
3. **具体的で細かく正確に表現する**（抽象的な言葉を避ける）
4. **状況に応じた表現**（いつ、どこで、どのように提示するか）

**悪い例:** 選手情報を自動表示する
**良い例:** 陸が週刊ページで選手名を見た時に、その選手が3週間前にも登場していたことを小さく表示し、「前も見ましたよ」と気づかせる

---

## 10個のアイデア

### アイデア1: 選手の再登場を自動で教える「前回登場」マーク

**具体的な仕組み:**

陸が今週の週刊ページを開いて選手名を見た時、その選手が過去の週刊ページに登場していた場合、選手名の横に小さく「前回登場: 第3週」と表示される。クリックすると、その週のページにジャンプする。

**ペルソナの体験:**
- 「あ、この選手前も見たんだ」と気づく
- 能動的に調べなくても、過去の記憶が呼び起こされる
- 「確か〇〇で優勝してた人か」と思い出す

**技術的実装:**
- Markdownファイル内で選手名をタグ化（例: `[[選手名]]`）
- ビルド時に選手の登場履歴をインデックス化
- 静的サイト生成時に「前回登場」リンクを自動挿入

**既存要素の組み合わせ:**
- 週刊更新の蓄積（既存）
- 選手名の記載（既存）
- 自動リンク生成（新）
- 登場履歴のインデックス（新）

### アイデア2: 「知ってる選手カウンター」の自然な増加を可視化

**具体的な仕組み:**

週刊ページのトップに「あなたが知ってる選手: 12人（先週より+2）」と表示される。陸が過去に2回以上登場した選手を「知ってる選手」としてカウントし、毎週の増加を見せる。

**ペルソナの体験:**
- 「先週より2人増えた」という成長を実感
- 調べていないのに、自然に知識が増えている感覚
- 「12人も知ってるんだ」という肯定感

**技術的実装:**
- LocalStorageで訪問履歴を記録
- 各選手の登場回数を集計
- 2回以上登場した選手を「知ってる選手」と定義
- 前週との差分を計算して表示

**既存要素の組み合わせ:**
- 選手の複数回登場（既存）
- LocalStorage（既存技術）
- カウンター表示（新）
- 成長の可視化（新）

### アイデア3: 対戦カードを見た瞬間に背景が自動で表示される「ミニ解説」

**具体的な仕組み:**

週刊ページで「〇〇選手 vs △△選手」という対戦カードが書かれている時、その直下に1-2行の自動ミニ解説が表示される。例：「前回対戦: △△選手が勝利（第5週）」「両者ともルーク使い」「〇〇選手は3週連続で上位入賞中」。

**ペルソナの体験:**
- 対戦カードを見た瞬間に「あ、因縁の対決か」と気づく
- 自分で調べなくても、文脈が自動で提示される
- 「前回見た対戦の続き」と認識できる

**技術的実装:**
- 過去の対戦履歴をデータベース化（YAML/JSONファイル）
- 選手の最近の成績を記録
- ビルド時に対戦カードを検出し、自動でミニ解説を挿入
- テンプレート化された解説文（「前回対戦: 〇〇」「〇〇使い vs △△使い」）

**既存要素の組み合わせ:**
- 対戦カードの記載（既存）
- 過去週の対戦履歴（既存）
- 自動解説生成（新）
- データベース化（新）

### アイデア4: 選手アイコン（使用キャラ）で視覚的に覚えさせる

**具体的な仕組み:**

陸が週刊ページで選手名を見る時、必ず選手名の横に使用キャラの小さなアイコンが表示される。例：「プロトバナム（ルークアイコン）」。同じ選手が次週も登場した時、同じアイコンが表示されるので、「あ、ルークのあの人か」と視覚的に記憶できる。

**ペルソナの体験:**
- 名前は覚えられなくても、「ルーク使いのあの人」と覚えられる
- 視覚的記憶が働く
- 「あのアイコン見たことある」という既視感

**技術的実装:**
- 選手データにキャラ情報を紐付け（YAMLファイル）
- キャラアイコンをSVG/PNGで用意
- Markdown記述時に選手名を書くと自動でアイコンが挿入される

**既存要素の組み合わせ:**
- 選手の使用キャラ情報（既存）
- アイコン表示（既存技術）
- 視覚的記憶のサポート（新）
- 自動挿入（新）

### アイデア5: 週をまたいだストーリーの自動連結「続き物」表示

**具体的な仕組み:**

今週の週刊ページで「〇〇選手が優勝」と書かれている時、過去3週間でその選手が登場していた場合、「ストーリー: 第3週で準優勝 → 第5週で3位 → 今週優勝」と自動で時系列が表示される。

**ペルソナの体験:**
- 「この選手、前から追ってたんだ」と気づく
- ストーリーとして記憶に残る
- 「調子上がってきてたんだな」と文脈を理解

**技術的実装:**
- 選手の週ごとの成績を記録
- 過去3-4週の履歴を自動で抽出
- 時系列で成績を表示
- 「上昇中」「安定」「復調」などのラベル自動付与

**既存要素の組み合わせ:**
- 週刊更新の蓄積（既存）
- 選手の成績記録（既存）
- 時系列の自動連結（新）
- ストーリー化（新）

### アイデア6: 「前回あなたが見た時」との状況比較

**具体的な仕組み:**

陸が週刊ページを開いた時、トップに「前回訪問: 2週間前（第8週）」「その時注目していた〇〇選手、今週も登場」と表示される。LocalStorageで前回の訪問週を記録し、その週に陸が見ていた選手が今週も登場していることを教える。

**ペルソナの体験:**
- 「あ、2週間ぶりか」と時間感覚を取り戻す
- 「前見た選手がまた出てる」と連続性を感じる
- 自分で覚えていなくても、システムが教えてくれる

**技術的実装:**
- LocalStorageで前回訪問日時・訪問週を記録
- 前回見たページの選手リストを保存
- 今週の選手リストと照合
- 共通選手を「また登場」として表示

**既存要素の組み合わせ:**
- LocalStorage（既存技術）
- 訪問履歴（既存）
- 選手の再登場（既存）
- 個人の状況に合わせた提示（新）

### アイデア7: キャラ使いとしての自動グルーピングで記憶フック

**具体的な仕組み:**

週刊ページで複数の選手が登場する時、使用キャラごとにグルーピングして表示される。例：「ルーク使い: プロトバナム、〇〇、△△」「ケン使い: □□、☆☆」。陸は「ルーク使いが3人出てる」と認識し、キャラごとに選手を覚えられる。

**ペルソナの体験:**
- 「ルーク使いはこの人たち」と塊で覚えられる
- 自分の使用キャラの選手に自然と注目
- キャラという記憶のフックを使える

**技術的実装:**
- 選手データに使用キャラを紐付け
- 週刊ページ生成時にキャラ別でグルーピング
- 「今週の〇〇使い」セクションを自動生成

**既存要素の組み合わせ:**
- 選手の使用キャラ情報（既存）
- グルーピング表示（既存技術）
- キャラ別記憶（新）
- 自動セクション生成（新）

### アイデア8: トーナメント進行の自動文脈化「今どういう状況か」

**具体的な仕組み:**

週刊ページでトーナメント情報が書かれている時、「現在TOP8進出中」「準決勝で敗退」など、進行状況を自動で簡潔に説明する一言が選手名の横に表示される。start.ggのような複雑な表を見なくても、文章だけで状況が理解できる。

**ペルソナの体験:**
- 「TOP8進出中」という一言で「すごいんだな」と理解
- トーナメント表を見なくても状況がわかる
- 「誰がどこまで勝ち上がってるか」が一目瞭然

**技術的実装:**
- トーナメントデータ（start.gg等）から進行状況を取得
- 「TOP8」「準決勝」「優勝候補」などのラベル自動付与
- 選手名の横に括弧書きで表示

**既存要素の組み合わせ:**
- トーナメント情報（既存）
- start.ggデータ（既存）
- 自動ラベル生成（新）
- 簡潔な文脈化（新）

### アイデア9: 「今週新しく知った選手」の自動ハイライト

**具体的な仕組み:**

陸が週刊ページを読み終えた後、ページ下部に「今週新しく知った選手: 〇〇選手、△△選手」と自動でハイライト表示される。過去に登場していない選手を検出し、「今週新しく出会った人」として記憶に残す。

**ペルソナの体験:**
- 「今週2人新しく知ったんだ」という発見
- 何気なく読んでいたが、「これが新情報だったのか」と認識
- 記憶に残りやすくなる

**技術的実装:**
- LocalStorageで過去に登場した選手リストを保存
- 今週のページの選手リストと照合
- 初登場の選手を検出
- ページ下部に「今週の新顔」として表示

**既存要素の組み合わせ:**
- 選手の登場履歴（既存）
- LocalStorage（既存技術）
- 新規選手の検出（新）
- ハイライト表示（新）

### アイデア10: 因縁・関係性の自動抽出と「ストーリー」化

**具体的な仕組み:**

陸が「〇〇選手 vs △△選手」という対戦カードを見た時、過去にこの2人が何度も対戦していた場合、「因縁の2人（過去3回対戦、2勝1敗で〇〇選手有利）」と自動で表示される。単なる対戦カードではなく、「物語のある対戦」として認識できる。

**ペルソナの体験:**
- 「この2人、ライバルなんだ」と気づく
- 対戦がドラマに見える
- 自分で調べなくても、因縁を知れる

**技術的実装:**
- 過去の対戦履歴をデータベース化
- 同じ組み合わせの対戦が複数回あれば「因縁」と判定
- 勝敗数を集計
- 「因縁の2人」「リベンジマッチ」などのラベル自動付与

**既存要素の組み合わせ:**
- 過去の対戦履歴（既存）
- 対戦カードの記載（既存）
- 因縁の自動検出（新）
- ストーリー化（新）

## アイデアの共通要素

### 「調べない」ペルソナに寄り添う設計

全てのアイデアに共通するのは：

1. **受動的でも知識が入る**: 陸が能動的に「調べる」必要がない
2. **自然な提示**: ページを開く、選手名を見る、という普通の行動の中で情報が提示される
3. **記憶のフック**: 視覚（アイコン）、時系列（ストーリー）、グルーピング（キャラ別）など、覚えやすい工夫
4. **成長の可視化**: 「知ってる選手が増えた」「新しく知った」と明示的に示す
5. **文脈の自動生成**: 因縁、過去の対戦、進行状況など、自分で調べなくても文脈が提示される

### 技術的制約内での実現

静的サイト・週刊更新・Markdown管理という制約の中で：

- **LocalStorage**: 個人の訪問履歴・成長を記録
- **ビルド時の自動生成**: Markdownから選手情報を抽出し、自動でリンク・解説を挿入
- **データベース化**: YAML/JSONで選手・対戦履歴を管理
- **テンプレート**: 「前回登場」「因縁の2人」など定型文を自動生成
